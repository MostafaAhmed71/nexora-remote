# إدارة الماستر — تطوير محلي غير منشور

أضيفت واجهة `/master` ومسارات API ومهاجرة `004_master_management.sql` وعميل إدارة في وكيل Windows. هذه الإضافات لا تغير نطاق أدلة الإصدار 0.3 القديمة؛ يلزم بناء الوكيل المحدث وتثبيته على الأجهزة المستهدفة.

## الوظائف

- إدارة أجهزة بالجملة: البحث والتصفية بالمجموعة والقاعة، التحديد الجماعي ونقل الأجهزة بين المجموعات. العملية بحد أقصى 100 جهاز وبمعاملة واحدة؛ فشل جهاز يُرجع العملية كلها.
- باقات وقت قابلة للإضافة والحذف، أو مدة مخصصة. بدء وقت جديد وزيادته وإيقافه مؤقتًا واستئنافه. الإيقاف المؤقت يقفل الاستخدام ولا يمنح وقتًا مجانيًا. «فتح وإلغاء المؤقت» يلغي الحد الزمني صراحة.
- قفل جماعي وفتح من حساب مالك أو مدير، مع مراجعة الصلاحيات على الخادم وسجل تدقيق. الواجهة تميز الحالة المطلوبة عن تأكيد التطبيق وتعرض عدم اتصال الإدارة وأخطاء التنفيذ.
- خريطة أجهزة بالقاعة والإحداثيات والملاحظات والحالة والوقت المتبقي. المجموعة تنظيم منطقي، والقاعة مكان فعلي مستقل.
- نقل ملفات إلى الجهاز بعد موافقة المستخدم محليًا، ومن الجهاز إلى الماستر باختيار المستخدم ملفًا في نافذة الإدارة. نقل على أجزاء مع تقدم وإلغاء وإعادة محاولة، دون تنفيذ الملفات تلقائيًا أو السماح بتصفح القرص عن بُعد.
- ملفات بحد 10 MiB للملف و50 MiB/100 ملف لكل جهاز. انتهاء الوصول بعد 24 ساعة؛ تنظيف الصفوف المنتهية يحدث عند طلب رفع أو مزامنة لاحق بالمؤسسة، وليس وعدًا بمحو القرص في وقت محدد. المحتوى مخزن في قاعدة البيانات، والخادم يستطيع قراءته. النقل عبر HTTPS في النشر الفعلي.
- وضع حصة مبدئي: ملفات تعريف بقائمة مسارات برامج محلية ومواقع HTTPS، تُعرض في مشغل واضح على الجهاز. **ليس حظرًا لبقية البرامج أو المواقع، ولا وضع امتحان آمنًا.** العزل الفعلي يحتاج تنفيذًا منفصلًا لسياسات Windows والكشك والمتصفح؛ لم يُنفذ هنا.

## تشغيل الجهاز المُدار

1. طبّق المهاجرات باستخدام حساب مالك قاعدة البيانات كالمعتاد.
2. ابنِ الوكيل المحدث؛ استعمل وضع الخدمة للتشغيل التلقائي، أو فعّل الاتصال يدويًا في وضع المستخدم.
3. تظهر نافذة `NEXORA — Master management (local consent)`. فعّل خيار السماح بإدارة الماستر على حساب Windows الحالي. التسجيل القديم وحده لا يمنح موافقة التحكم بالوقت.
4. من الويب اختر المؤسسة ثم «لوحة الماستر»، وحدد الأجهزة وطبّق الإجراء. تحقق من «تم التطبيق»، لا من نجاح حفظ الطلب وحده.
5. استلام الملفات يتطلب الضغط على Accept file في نافذة الجهاز. تُحفظ باسم يتضمن معرف النقل داخل `NexoraRemote Inbox` بمجلد المستخدم. إرسال ملف للماستر يتم من زر اختيار الملف في النافذة نفسها.

## حدود القفل والمؤقت

المؤقت المحفوظ محليًا موقع من الخادم ومشفر بـDPAPI لحساب Windows. يستمر أثناء انقطاع الشبكة في العملية الجارية، ويستعاد من التخزين بعد بدء العامل مجددًا حتى إذا تعذر الوصول للخادم. الساعة الرتيبة تمنع إرجاع ساعة النظام من تمديد الوقت أثناء نفس التشغيل. تغيير الساعة أو الملفات بواسطة مسؤول محلي وإعادة التشغيل ليس حدًا أمنيًا مضمونًا.

القفل نافذة تغطي سطح المكتب للمستخدم المتعاون، وليس قفل Windows أمنيًا أو إيقاف تشغيل. المستخدم يستطيع سحب الموافقة محليًا؛ لا تعطيل لـTask Manager أو شاشة الأمان أو وسائل الاسترداد. لا تدّعي النسخة منع التحايل أو اعتمادها كسيبر مدفوع أو بيئة امتحانات. توقيت ما قبل تسجيل دخول Windows ودورة reboot/WTS الكاملة على جهازين لم تختبر هنا.

أوامر الإدارة مستقلة عن منح مشاهدة الشاشة القصيرة. كل مزامنة تستخدم تحديًا أحادي الاستخدام وإثبات مفتاح الجهاز على كامل الطلب؛ الرد موقع ومربوط بالجهاز والمؤسسة والتحدي. الوكيل والعامل يتحققان قبل تطبيق الحالة. حفظ revision يمنع تراجع الحالة داخل التشغيل؛ البيانات المعادة محليًا بواسطة المستخدم نفسه ليست حماية ضد مهاجم محلي.

## التحقق

اختبارات API حقيقية على PGlite تطبق RLS وصلاحيات تشغيل مقيدة، وتغطي الأدوار وعزل المؤسسة والتراجع الجماعي والمؤقت والملفات وإعادة المحاولة وإثبات الهوية. توجد عقود C# للتوقيع والتحدي والمؤقت والاستعادة، واختبار Playwright لمسار لوحة الماستر عبر الخادم الحقيقي بجهاز اختبار محاكى. هذه الاختبارات لا تعادل تجربة نقل ملفات وقفل فعلية على جهاز Windows ثانٍ.

أوامر التحقق:

```text
npm run typecheck
npm test
npm run build
npm run lint
dotnet run --project tests/management-contract/Management.Contract.csproj -c Release
npm run test:e2e
```

المشغل التجريبي يدعم `E2E_ORIGIN` لعنوان loopback و`E2E_PORT` لمنفذ API. Vite يدعم `NEXORA_API_TARGET` لتجنب تعارض مشروع محلي آخر. حساب المشغل التجريبي وبياناته مؤقتان ولا يصلحان كإعداد إنتاجي.
