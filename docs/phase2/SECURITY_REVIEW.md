# Phase 2 source review and regression evidence

Scope: executable server, SQL, browser, Agent, installer and workflows from Phase 1 commit aa28eca. This is an engineering source review and regression suite, not an independent penetration test or a claim of no vulnerabilities.

| Confirmed defect or gap                                                                               | Change                                                                                                                                                                       | Evidence                                                                                                                    |
| ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| Phase 1 socket tickets were carried in query URLs and could enter proxy/access logs                   | Reject URL credentials; Agent bearer header, browser `nexora.v2` plus one-use ticket subprotocol; redact credential headers                                                  | API tests reject URL/anonymous/replayed tickets; browser E2E uses real cookie-bound handshake                               |
| Viewer authorization was checked before asynchronous DB work without rechecking live socket ownership | Check the current viewer before and after awaited authorization; expired timers cannot end a replacement socket                                                              | Regression deliberately suspends an authorization result, replaces the viewer, then proves its stale input is not forwarded |
| A viewer ticket was a transferable bearer independent of its issuing login                            | Bind ticket to issuing session digest, cookie and exact browser Origin                                                                                                       | Wrong-login-cookie redemption rejected even with the issued ticket                                                          |
| Agent ping was discarded while frame validation was busy                                              | Process heartbeat and health independently from droppable frames; bounded frame work remains                                                                                 | Browser integration exercises heartbeats alongside streaming                                                                |
| Reconnecting an Agent could leave prior desktop rows active                                           | End prior grants and viewer sockets on Agent replacement/disconnect; fresh proof and authorization are required                                                              | API lifecycle tests; conditional genuine Windows loopback reconnect test                                                    |
| Remote grant could outlive an about-to-expire login                                                   | Cap signed grant expiry to the authorizing login expiry as well as five minutes                                                                                              | API test shortens the login lifetime and asserts the issued grant bound                                                     |
| Agent cancellation could bypass local input release                                                   | Cancellation-safe cleanup in `finally`; bounded sends/IPC and missing-pong detection                                                                                         | Agent build; Windows native post-revoke input rejection; loopback cancellation/reconnect test                               |
| Failed Windows key releases were forgotten                                                            | Keep failed releases for retry on the normal desktop; serialize input/release bookkeeping                                                                                    | Source path inspected; lock/UAC race validation still required in the lab                                                   |
| Browser DELETE requests unconditionally declared JSON without a body                                  | Set Content-Type only when a body exists                                                                                                                                     | Real viewer E2E terminates its session through Fastify                                                                      |
| Device access was organization-role-wide without a device ACL                                         | Add forced-RLS device ACL with composite tenant keys; enforce by default for existing and new devices; check live ACL per session/input/frame; ACL changes end active grants | API tests cover device ACL/RBAC independence, invalid/cross-tenant ACL targets and existing tenant tests                    |
| MFA recovery and configured production delivery were absent                                           | One-use hashed recovery codes after password+TOTP; explicit HTTPS delivery adapter with secret, timeout and redirect rejection                                               | Recovery replay/hash tests; delivery adapter mock tests; no real mail sent                                                  |
| Phase 1 installation was per-user with no service                                                     | Protected Program Files service; machine DPAPI key plus SYSTEM/Admin DACL; visible user worker and authenticated bounded local pipe                                          | Native pipe PID, DACL, framing and DPAPI tests; machine install/start/stop/reinstall/uninstall test                         |

No cross-tenant IDOR was demonstrated in the original tenant-scoped API tests; those protections were preserved and expanded. No Windows passwords are collected or stored. Private RSA keys never cross into the interactive worker, browser or Git. A worker receives only public identity fields and signed grants over the authenticated pipe. Files and clipboard are NOT exposed as implemented capabilities.

Remaining security gates: independent penetration review; full service→WTS worker→IPC→relay testing after machine enrollment/reboot; UAC/locked desktop transition races; multi-user/RDP session policy; complete auth/platform audit, MFA recovery generation concurrency review, stale-session-row cleanup after backend restart, retention/export/tamper evidence; production delivery-provider integration; signing certificate lifecycle. The relay terminates TLS and can observe frames (no E2E media encryption claim). Production origin requires HTTPS. Loopback HTTP is for isolated validation only.

Audit retention design: retain session authorization/termination and privileged device/member changes under the existing append-only runtime grants. A future retention worker must use a dedicated restricted maintenance role, configurable organization retention and legal hold, export hashes and deletion records; it must never use the web runtime role to modify historical audit rows. This maintenance worker is not implemented.
