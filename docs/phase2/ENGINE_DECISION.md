# Screen engine decision and implementation

| Path                       | Assessment                                                                                                                                                                          | Current state                                                                             |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- |
| GDI + JPEG + WSS           | Works with the existing engine and can be validated against a visible desktop marker without a display-driver dependency. Full-frame CPU cost and TCP head-of-line blocking remain. | Implemented fallback, bounded width/quality/FPS/frame size and explicit monitor selection |
| Desktop Duplication / DXGI | Dirty/move regions and GPU surfaces are appropriate for a higher-performance capture backend. Requires adapter/output reset handling and driver validation.                         | Evaluated, not implemented                                                                |
| Windows Graphics Capture   | Supported Windows capture API; requires correct consent/capture-item and WinRT/Direct3D lifetime handling.                                                                          | Evaluated, not implemented                                                                |
| H.264 hardware encoding    | Potentially reduces network and CPU cost; requires a measured encoder/device pipeline and compatible decoder, reset/keyframe/bitrate policy.                                        | Not implemented                                                                           |
| WebRTC                     | Standard encrypted real-time transport with congestion control; requires ICE/signaling/TURN policy and complete transport authorization.                                            | Not implemented; no fake WebRTC path or third-party desktop engine                        |

This phase improves the functioning fallback instead of naming unused GPU/video APIs. No claim is made that JPEG is the final commercial engine or that it achieves H.264 efficiency. Microsoft references: https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/desktop-dup-api and https://learn.microsoft.com/en-us/windows/win32/services/interactive-services .

Implemented controls: width 320–2560, JPEG quality 15–85, FPS target 1–15 and monitor index 0–31 (worker clamps to current display count). Each frame carries its session UUID, is capped at 2 MiB and is checked against live DB authorization before relay. Slow viewers and concurrent frame validation drop obsolete complete frames; ordered control input is never intentionally dropped. FPS adjusts conservatively using observed capture/send time, not an unmeasured bandwidth estimator. Viewer displays decoded FPS, received bytes/bitrate and browser/server RTT; it does not label RTT as Windows end-to-end latency.

GDI capture reads the actual selected screen dimensions each frame, so resolution changes recreate the bitmap and canvas. PerMonitorV2 is configured; coordinate mapping handles negative virtual-screen origins and uses 64-bit multiplication. Physical resolution changes, DPI, multiple displays, monitor removal and rotation still require the lab matrix. The loopback quality test changes encoded resolution, not the Windows display mode.

Remote input includes normalized moves, left/right press/release (browser double-click is the ordered pair of clicks), wheel, modifiers, navigation/extended VK flags and Unicode text injection. Unicode permits Arabic text independently of host keyboard layout. It is not proof of every Arabic IME/physical-layout shortcut. The worker must be on the normal desktop, verify a signed active grant, reject duplicate sequence numbers and respect local disable. UAC, elevated applications beyond UIPI, secure desktop and logon remain unsupported.
